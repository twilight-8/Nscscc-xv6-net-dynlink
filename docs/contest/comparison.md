# 与类似项目的对比分析

本文从功能、架构设计、代码规模、性能、文档与测试、创新性六个维度，将本项目与赛题指定的两个参照项目及 Linux/xv6 原版进行对比。参照项目数据来自对其公开仓库的实地取证（2026-08-07 克隆分析），取证要点见 `../notes/08-references.md` 参照项目一节。

## 对比对象

- **SpringOS（2025 年内核赛道，静春山队）**：xv6-riscv 基线 + 仅 EXT4（集成 lwext4 第三方库），RISC-V/LoongArch 双架构并适配真实开发板。
- **RuOK（2025 年内核赛道）**：C++ 重写内核（xv6 设计思路），FAT32 + ext4 + ramfs，RISC-V/LoongArch 双平台并适配真实板卡。
- **Linux**：工业级参照系（仅用于架构对比）。
- **xv6-riscv rev5 原版**：本项目基线。

## 分析

**功能维度**：本项目是三者中唯一实现“原生 xv6 与两个外来文件系统共存并可跨系统互拷”的（这正是本赛题与 2025 年内核赛道的目标差异）。SpringOS 押注单一 EXT4 的深度（extent、日志、目录索引），RuOK 追求文件系统种类与系统调用覆盖；本项目追求的是**赛题边界内的完整性与正确性证据链**。

**架构设计维度**：Linux 的 VFS 是完整的对象模型（dentry/inode/superblock/file 四层），体量远超教学需要；两个参照项目分别为目录式 VFS 和 C++ 类体系。本项目用薄 ops 分发表完成分发，以可睡眠操作锁串行化挂载拓扑修改，并以四态表完成发布、失败回滚、unlink 可见性和安全卸载，是“教学可讲清”的小型 VFS 形态；HAL 亦然（RISC-V 46 行、LoongArch 52 行，结构对称，而参照项目或无独立 HAL、或为双层抽象）。

**代码规模维度**：本项目标准 diff 为 +6405/−113（62 个文件），其中 37 个新增文件贡献 +5603 行，25 个 rev5 既有文件为 +802/−113；排除纯空白新增/删除行后为 +5602/−106，共 5708 行非空白文本变更。整体仍比参照项目小一个数量级。赛题要求“增加的代码尽量少”，本项目的实现密度（每千行实现的功能点）更高；SpringOS 的体量中 56% 为第三方 lwext4 库，属于“集成”而非“实现”。

**性能维度**：本项目保留了本轮 P0 修复前采集的 RISC-V 阶段性微基准：当时 VFS 分发写路径差异约 18%、读路径在计时粒度内无差异，fat32 两项优化将同负载写/读分别提速约 4.8 倍/21 倍。这些数据用于解释优化方向，不冒充最终源码性能；最终版本须重新采集后才能更新结论。参照项目公开仓库中未见可复现的性能数据。

**文档与测试维度**：本项目具备自动化回归（11 个测试点 × 2 个架构 = 22 项执行）、双架构完整 usertests、挂载生命周期与 SMP 并发证据、e2fsck 第三方校验与证据归档；两个参照项目均有文档积累，但 RuOK 无自动化测试证据，SpringOS 的测试偏比赛评分脚本驱动。

**创新性维度**：见 `innovation.md`；其中“单一 virtio 盘三文件系统布局”与“中断看门狗”是两个参照项目均不具备的机制。

## 结论

本项目与参照项目的定位不同：它们向“功能更全的操作系统”演进，本项目向“设计精巧、可验证的教学操作系统”收敛。在赛题设定的目标（三文件系统、双平台、少而精的增量、稳定性证据）上，本项目的完成度与证据链完整度更高；在功能广度（真机适配、busybox 用户态、网络）上，参照项目覆盖更广，但其已超出本赛题要求范围。
