# 性能测试与分析

本文只报告有可核对原始记录的数据，并明确版本边界。下列文件系统吞吐数据由 `vfsbench`（源码 `src/user/vfsbench.c`）在 QEMU RISC-V 中采集，计时单位 tick = 10ms，负载为 128KiB 文件 × 5 轮完整创建/写/读/删循环；但记录生成于本轮冷 inode、挂载并发和跨后端 exec 三项 P0 修复之前，因此只作为阶段性优化证据，不代表最终源码性能。现有 `tests/evidence/bench-loongarch.txt` 实际误采集为 RISC-V 构建与运行记录，也不得作为 LoongArch 性能证据。最终性能结论须在冻结源码上重新采集后更新。

## 1. 历史 VFS 分发层开销（RISC-V，修复前阶段记录）

同一负载，原版 rev5（无 VFS）与本项目（VFS 分发路径）对比（RISC-V）：

| 负载 | rev5 原版 | 本项目 | 差异 |
|---|---|---|---|
| 写 5×128KiB | 50 ticks | 59 ticks | +18% |
| 读 5×128KiB | 5 ticks | 4 ticks | 量化粒度内无差异 |

阶段性结论：当时版本在该写密集微基准上的差异约为 18%，读路径差异低于 tick 量化粒度。该记录可用于估计薄分发成本，但不能直接外推为最终源码结果。

## 2. 历史三后端吞吐对照（RISC-V，128KiB×5，ticks）

| 后端 | 写/读 |
|---|---|
| xv6 根文件系统 | 59 / 4 |
| ext2 | 40 / 5 |
| fat32 | 57 / 4 |

解读：ext2 写快于 xv6 根文件系统属预期——xv6 文件系统所有写经日志双写，ext2/fat32 后端直接写回；fat32 经优化后与 xv6 根相当。

LoongArch 三后端吞吐暂不列数值。答辩与提交材料不得把上述 RISC-V 数据改写为 LoongArch 结果；真实数据应由 `ARCH=loongarch` 构建、`qemu-system-loongarch64` 运行的完整日志支撑。

## 3. fat32 优化前后历史对比（RISC-V，128KiB×5，ticks）

| 版本 | 写 | 读 |
|---|---|---|
| 无任何优化 | 273 | 86 |
| 仅 next-free 提示 | 168 | 102 |
| next-free + 链漫游缓存 | **57** | **4** |

阶段性结论：next-free 提示消除了分配的 O(n²) 扫描；链漫游缓存消除了 `cluster_at` 的 O(n²) 重扫。三组历史记录支撑优化方向和当时版本的相对收益，但不替代最终源码复测。

## 4. 构建、启动与体积

本轮源码修复后尚未归档可复核的双架构构建时间、启动时间和内核体积原始记录，因此不在最终材料中列数值。若用于答辩，应在最终源码上分别完成三次冷构建、三次直接 QEMU 启动，并记录工具链版本、命令、每次结果和内核文件哈希；启动时间以捕获 `init: starting sh` 为终点，不能混入 `make qemu` 的依赖检查时间。

## 5. 复现方法

```sh
# 本项目三后端（先挂载 ext2 与 fat32）
vfsbench /rb 5 128          # xv6 根
vfsbench /mnt/eb 5 128      # ext2
vfsbench /fat/fb.bin 5 128  # fat32
# rev5 对照：在 xv6-riscv-src 构建中加入同一基准程序后运行
vfsbench /rb 5 128
```
