# 性能测试与分析

全部数据来自 `vfsbench` 基准程序（源码 `src/user/vfsbench.c`）在 QEMU 中的实测，原始输出归档于 `tests/evidence/bench-*.txt`，可用相同命令复现。计时单位 tick = 10ms；测试负载为 128KiB 文件 × 5 轮完整创建/写/读/删循环。

## 1. VFS 分发层开销（评审预设问题：“薄 VFS 引入多少开销”）

同一负载，原版 rev5（无 VFS）与本项目（VFS 分发路径）对比（RISC-V）：

| 负载 | rev5 原版 | 本项目 | 差异 |
|---|---|---|---|
| 写 5×128KiB | 50 ticks | 59 ticks | +18% |
| 读 5×128KiB | 5 ticks | 4 ticks | 量化粒度内无差异 |

结论：VFS 薄分发（一次函数指针间接调用）在写密集微基准上引入约 18%开销，读路径开销低于 tick 量化粒度。该开销来自每层调用的间接跳转，与功能收益（多文件系统共存）相称。

## 2. 三后端吞吐对照（本项目，128KiB×5，ticks）

| 后端 | RISC-V 写/读 | LoongArch 写/读 |
|---|---|---|
| xv6 根文件系统 | 59 / 4 | 69 / 4 |
| ext2 | 40 / 5 | 44 / 5 |
| fat32 | 57 / 4 | 63 / 5 |

解读：ext2 写快于 xv6 根文件系统属预期——xv6 文件系统所有写经日志双写，ext2/fat32 后端直接写回；fat32 经优化后与 xv6 根相当。

## 3. fat32 优化前后对比（RISC-V，128KiB×5，ticks）

| 版本 | 写 | 读 |
|---|---|---|
| 无任何优化 | 273 | 86 |
| 仅 next-free 提示 | 168 | 102 |
| next-free + 链漫游缓存 | **57** | **4** |

结论：next-free 提示消除分配的 O(n²) 扫描（写 −38%）；链漫游缓存消除`cluster_at` 的 O(n²) 重扫（写合计 −79%、读 −95%）。两个优化的叠加效应均有独立数据支撑。

## 4. 构建、启动与体积

| 指标 | RISC-V | LoongArch64 |
|---|---|---|
| 全量构建（make clean 后） | 约 3.0 s | 约 3.1 s |
| 启动到 shell（直接启动 QEMU） | 约 0.2 s | 约 0.2 s |
| 内核体积（kernel/kernel） | 444,368 B | 519,408 B |

测量方法说明：启动时间以直接调用 QEMU、捕获 `init: starting sh` 输出为准（三次取典型值）。若经 `make qemu` 启动，测量会混入 make 的依赖检查与冷缓存开销（首轮可达 3 秒量级），不能作为启动指标——本文档以直接启动数据为准。

## 5. 复现方法

```sh
# 本项目三后端（先挂载 ext2 与 fat32）
vfsbench /rb 5 128          # xv6 根
vfsbench /mnt/eb 5 128      # ext2
vfsbench /fat/fb.bin 5 128  # fat32
# rev5 对照：在 xv6-riscv-src 构建中加入同一基准程序后运行
vfsbench /rb 5 128
```
