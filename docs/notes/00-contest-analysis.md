# 00 赛题分析

## 赛题任务拆解

题目：扩充 xv6-riscv 第 5 版，增加虚拟文件系统（VFS）与硬件抽象层（HAL）功能。硬性任务五条：

|   | 任务 | 本项目的应答 |
|---|---|---|
| 1 | 同时支持 xv6、ext2、fat32 | 薄 VFS 分发层 + 两个自研后端，单盘三区段共存 |
| 2 | 同时支持 RISC-V、LoongArch | 对称薄 HAL + `arch/loongarch/` 移植层 |
| 3 | 两平台通过自带测例 | `test_baseline`（usertests 双架构，含完整版） |
| 4 | 完成指定 VFS 测试用例 | 官方测例逐字节入库 + 官方流程复刻（`public_vfs`） |
| 5 | 提交与 rev5 的 diff | 基线锚定 + 可复现的 diff 生成（`../contest/baseline.md`） |

约束条件：增加的代码尽量少、系统运行稳定、设计精巧的教学操作系统。

## 评审要点拆解（各占 20%）

| 维度 | 评分依据 | 本项目的应答 |
|---|---|---|
| 设计精巧度 | 文档 + diff 度量 | 薄 VFS（507 行）、薄 HAL（RISC-V 46 行/LoongArch 52 行）、最小侵入修改 |
| 功能实现完成度 | 功能覆盖面 | 三文件系统 + 双平台 + 双间接 + LFN 读 + SMP 正确性 |
| 运行稳定性 | 实测 | 11 个测试点 × 2 个架构 = 22 项执行 + 完整 usertests + SMP + e2fsck |
| 文档质量 | 文档体系 | docs/ 三层结构（工程/笔记/赛事） |
| Demo 质量 | 视频 + 答辩 | 按 `../contest/video_script.md` 分镜录制 |

另有提交规范（出自赛题通知原文）：分阶段多次提交（初赛 ≥8 次、决赛 ≥4 次、附详细注释）；提交内容考察独立完成度、活跃度、完整性、创新性、可重现性。

## 策略结论

1. 代码以“少而精”为主线：一切功能在赛题边界内做深，不做范围外功能。
2. 稳定性以“可复现证据链”为目标：每个声明都有一条命令可验证。
3. 文档按评审条目对题写作（contest/），工程深度由活文档承担（根部）。
4. 提交按日推进、单笔主题单一、注释完整。

## 风险登记

- 上游测例动态扩充 → `tests/VFS_TESTS_PIN.txt` 锚定 + 定期复查。
- 评测环境差异 → `check_env.sh` + Dockerfile 双保险。
- 新增功能的连带缺陷 → 任何代码改动过推送门禁双项。
