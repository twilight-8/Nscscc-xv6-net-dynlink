# 02 文件系统调用链精读（fs/bio/log/sysfile）

本篇记录对 xv6 原生文件系统调用链的精读结论，重点是后来修复工作中反复用到的几个不变式。

## 一次 write 的完整路径

```text
sys_write → filewrite → writei → bmap → bread/bwrite（bio.c）
                                   → virtio_disk_rw（virtio_disk.c）
              ↑ 全程处于 begin_op/end_op 事务内（log.c）
```

## 关键不变式

1. **iget/iput 配对**：`iget` 只查缓存并增加引用计数；`iput` 在`ref==1 && nlink==0` 时负责截断与释放。xv6 原生语义里，“unlink 一个仍被引用的 inode”不立即释放资源——这是 B2 修复对齐的目标行为。
2. **ilock 的惰性填充**：磁盘 dinode 仅在 `valid==0` 时读入内存；命中缓存时内存状态优先于磁盘——B1 修复恢复的就是这条约定。
3. **iupdate 是唯一的内存→磁盘回写点**：它与 ilock 的拷贝尺寸必须严格等于磁盘 dinode 的 `addrs` 尺寸——P4 拷贝越界缺陷正是破坏这条约定（多写 4 字节覆写相邻 dinode）。
4. **日志层只服务 xv6 后端**：ext2/fat32 后端的写不经日志，崩溃一致性由“写直达 + 同步元数据”换取，这是明确的设计取舍（见 [design.md](../design.md)）。
5. **缓冲区锁的副作用**：`bread` 返回的缓冲块持有睡眠锁，位图等元数据的读改写在单缓冲上天然串行——ext2 分配器依赖它，而 fat32按字节接口绕开了它（这正是 C1 竞争只在 fat32 出现的原因）。

## 阅读方法备注

读这类代码时，先把“谁持有锁、谁可能睡眠、谁会写盘”三个问题标在函数边界上，再推演并发交错；本项目全部并发缺陷（B1/B2/C1/P4/P5）都可以用这个三步法静态推演出来。
