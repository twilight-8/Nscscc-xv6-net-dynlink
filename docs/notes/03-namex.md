# 03 路径解析与目录项机制精读（namex）

本篇记录对 xv6 路径解析层（`skipelem`/`namex`/`namei`/`nameiparent`）以及本项目挂载遍历扩展的精读结论。

## 原生机制要点

1. `skipelem` 把路径按 `/` 切出单个分量，**复制到 `char name[DIRSIZ]`** 时超过 14 字符的部分被静默截断——这不是错误处理，是命名空间的固有上限。本项目 ext2 长名别名与 fat32 LFN 匹配规则都以这个事实为前提设计（只需装配/比较前 14 字符）。
2. `namex` 逐级调用后端的 `lookup`；`.`/`..` 由后端目录项直接提供。
3. `namei` 返回最终 inode，`nameiparent` 返回父目录并分离出末级分量名。

## 本项目在路径解析上的扩展点

1. **挂载点跳转**：向下查到被挂载目录时切换到挂载文件系统的根inode；`vfs_lookup` 中对 `..` 做反向判断——挂载根的 `..` 回到挂载点的父目录（`vfs.c` 中按挂载表匹配并 `idup` 父目录）。
2. **挂载点保护**：三条 unlink 路径用 `vfs_mountpoint()` 判断目标是否正被用作挂载点，是则拒绝删除（B3）。
3. **exec 根目录回退**：裸命令名（不含 `/`）在当前目录解析失败时以`/` 前缀重试一次，使官方流程在 `/tests` 下可运行（P1）。
4. **长名别名查找**：ext2 对恰为 14 字符的查询名做唯一前缀别名匹配（精确短名优先），fat32 经 LFN 链装配后按同一规则匹配。

## 易错点记录

- 截断后的 14 字符名字**可能没有 NUL 结尾**，任何比较必须先定长再`memcmp`，不能依赖字符串函数。
- `..` 的跨挂载处理要保证引用计数平衡（`idup` 不多不少），这是审查时专门复核过的点。
